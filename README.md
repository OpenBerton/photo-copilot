# Photo Copilot

FYP 攝影輔助應用，協助使用者理解場景、選擇參考照片並獲得構圖及相機參數建議。

## 目前進度

已加入相機授權、即時預覽、拍攝與相簿保存。首次開啟會直接顯示 Android 系統的鏡頭權限視窗，允許後進入預覽，再按圓形快門拍照；優先使用後置鏡頭，沒有時使用前置鏡頭。已加入鏡頭切換、縮放、閃光燈、九宮格與本機示範參考照片選擇。場景分析、推薦算法、輪廓疊圖與拍攝建議尚未實作，算法與執行位置待實驗決定。

## 專案內容

- `frontend/`：完整 Android Studio 專案，只有一個 app 模組。
- [ARCHITECTURE.md](ARCHITECTURE.md)：功能邊界、程式放置規則與開發順序。
- `.gitignore`：排除本機設定、編譯產物及密鑰。

## 在 Android Studio 啟動

1. Clone 整個 repository，在 Android Studio 開啟 `frontend/`。
2. 使用支援 AGP 9.4 的 Android Studio（例如 Quail 4），Gradle JDK 選 Android Studio 內附 JDK。
3. 按提示安裝 Android SDK Platform 37、Build Tools 36.0.0，等待 Gradle Sync 完成。首次同步需要網絡。
4. 選擇 Android 8.0（API 26）或以上的模擬器／手機，以 app 設定按 Run。

固定版本：AGP 9.4.1、Gradle 9.6.0、compileSdk／targetSdk 37，minSdk 26。Java 原始碼相容級別是 11，與執行 Gradle 所用 JDK 不同。
使用 AndroidX ComponentActivity、XML Views 及 CameraX 1.6.2；相機綁定畫面生命週期，切到背景時停止使用，返回時恢復。預覽保持比例，部分螢幕會留黑邊。

## 畫面原則

相機畫面以預覽及圖示為主，避免常駐標題、路徑說明和按鈕文字。快門採無文字圓形按鈕，保留螢幕閱讀器名稱。拍攝時以短暫閃白、保存進度環及縮圖更新提供回饋，只有授權和錯誤需要文字提示。

預覽以外的背景、預覽留邊及系統列區域使用純黑色。畫面依可用空間安排預覽和控制區，避開系統列與螢幕缺口；影像維持 FIT_CENTER 比例，不以固定像素尺寸拉伸或裁切來填滿不同螢幕。
相機主畫面的控制項以裝置本身為基準固定排列，旋轉手機時不切換另一套橫向版面。快門保留在同一個實體邊緣，縮放、最近照片、翻轉、閃光、參考及九宮格入口維持原本相對位置；只有圖示、倍率文字及縮圖轉向目前螢幕方向。預覽在相同取景區內維持比例，系統列及缺口仍保留安全空間。

## 相機控制

- 第一次使用相機時直接呼叫系統授權視窗，不先顯示自製說明頁。視窗的文字及樣式由 Android 提供，已有權限時直接進入預覽。
- 拒絕後只顯示簡短提示與「開啟相機」，由使用者點按才再次詢問；重新開啟或旋轉不會自動反覆彈窗。系統已不再詢問時改為「前往設定」，從設定授權後返回會恢復預覽。

- 以下「上／左／右」以裝置原本方向為基準，手機旋轉後仍保留這些相對位置。
- 快門右側的鏡頭圖示：切換前後鏡頭；只有一個鏡頭時停用。
- 頂部閃光圖示：關閉 → 自動 → 開啟，設定只影響拍照，不是常亮手電筒；沒有閃光燈時停用。
- 快門上方、預覽以外，平時顯示鏡頭支援的常用倍率按鈕（廣角最小倍率、1×、2×、5×）。點按直接選擇；左右拖動同一區域才切換為直線刻度，放手後恢復按鈕，上方數字持續顯示實際倍率。切換時控制區高度固定，不改變預覽大小。
- 刻度中央指示固定，整條刻度隨手指左右移動，兩端漸淡；向左拖動放大、向右拖動縮小，開始拖動不跳倍率，放手不誤選原按鈕。也可雙指縮放；點按上方倍率切換常用倍率，長按重設為 1×。無障礙「展開／收合」可切換細調刻度；不支援縮放時停用。
- 快門左側顯示此 App 最近保存照片的縮圖，點按交由手機圖片檢視器開啟。尚未拍攝或照片已刪除時停用，不掃描整個相簿。
- 頂部九宮格圖示：開啟／關閉輔助線，只對齊實際影像範圍，不畫在黑邊，也不寫入照片。
- 旋轉畫面保留鏡頭、閃光、倍率及九宮格設定；切換鏡頭時倍率重設為 1×，不支援閃光的鏡頭自動關閉閃光。
- 拍攝中暫停鏡頭、縮放及閃光操作；控制採圖示，只有倍率顯示簡短數字。

## 拍攝與保存

- 照片以 JPEG 存入手機相簿的 `Pictures/PhotoCopilot`，每張使用唯一檔名。
- 保存中停用快門並顯示進度環，完成後更新縮圖及恢復拍攝；失敗顯示提示，清理本次未完成的相片項目。
- Android 10+ 僅要求相機權限；Android 8／9 第一次拍照時另要求儲存權限，拒絕後可重試或前往設定。
- 檔案寫入在背景執行；不要求讀取其他照片、位置或網絡權限。
- 最近照片只記錄本 App 成功保存的 URI；縮圖在背景載入。Android 8／9 使用 AndroidX ExifInterface 處理照片旋轉及鏡像資訊。
- 畫面重建時，未開始的拍攝會取消；已進入保存的工作會收尾。系統終止 App 時不保證保存完成，成功照片以相簿為準。

## 參考照片

- 頂部照片圖示開啟黑色底部面板，左右滑動查看四張本機示範照片（兩張人像、兩張風景）；面板標示「示範照片」，不代表分析或推薦結果。
- 點選縮圖返回相機，入口改為所選照片的小縮圖；再次開啟會標示並捲到已選照片。可換圖，或按「取消選擇」清除。
- 關閉、返回或點面板外保留選擇；旋轉或系統重建畫面時保留所選 ID 和面板開啟狀態。這不是跨次啟動的永久偏好設定。
- 示範圖片隨 App 提供，不讀取使用者相簿，也不需要網絡；縮圖在背景解碼。沒有資料或載入失敗時顯示簡短提示，失敗圖片不可選，重新開啟面板可重試。
- 目前選擇僅供流程使用，不改變預覽或保存的照片；之後才加入參考輪廓與對齊操作。
- 四張照片由內建 image_gen 工具生成，人物及場景為示範素材；[素材路徑與完整提示詞](ARCHITECTURE.md#示範圖片來源)記錄在架構文件。

## 命令列建置

將 JAVA_HOME 指向相容的 JDK，並透過 Android Studio 或本機 `frontend/local.properties` 設定 SDK 路徑，然後執行：

```sh
cd frontend
./gradlew :app:assembleDebug :app:lintDebug
```

Windows 使用 `gradlew.bat`。本機 SDK 路徑不提交到 Git；不要將自己的絕對路徑寫進共用建置設定。
APK 產生於 `frontend/app/build/outputs/apk/debug/app-debug.apk`。
相機裝置整合測試放在 `frontend/app/src/androidTest/`。需要已啟動且有可用相機的測試裝置，並以全新安裝或只在測試裝置清除此 App 資料作為前置條件。測試會授予相機權限（Android 8／9 也授予儲存權限），拍攝兩張虛擬照片並只刪除本次新增的測試照片，請勿對日常使用中的 App 資料執行清除。

```sh
adb shell pm clear com.yrf3.photocopilot
./gradlew :app:connectedDebugAndroidTest
```

若第一次尚未安裝 App，第一個指令可省略。

版面及參考照片測試會先授予鏡頭權限，避免系統視窗遮住被測畫面。原生權限流程另以全新測試資料獨立執行，以下 `permission_case` 可改為 `retry`（拒絕後重試並允許）或 `blocked`（Android 11+ 重複拒絕及設定入口）。每個案例執行前只清除此測試 App 資料；`allow` 也會在系統視窗開啟時旋轉手機再允許。

```sh
adb shell pm clear com.yrf3.photocopilot
adb shell am instrument -w \
  -e class com.yrf3.photocopilot.CameraPreviewTest \
  -e require_fresh_permission true -e permission_only true \
  -e permission_case allow \
  com.yrf3.photocopilot.test/androidx.test.runner.AndroidJUnitRunner
```

## 裝置驗證

2026-10-20：Debug APK 及測試 APK 編譯成功，lint 為 0 錯誤、6 個警告（工具更新、既有備份設定、主畫面的雙層權重、主畫面／參考面板的黑色背景重繪，以及預覽轉向容器被標示可能多餘）。內外預覽容器分別保留裝置位置及補償內容方向，有實際用途；沒有停用檢查。

系統授權提示版本在同一個 API 37（Android 17）模擬器完成 4 次獨立權限流程測試：手機 1080×2400／420dpi 的首次允許、拒絕後重試、重複拒絕後設定入口，以及平板 1600×2560／320dpi 的首次允許。首次允許案例包含系統視窗開啟時旋轉，拒絕案例包含畫面重建後不自動再次詢問；已檢查手機及平板提示截圖。另在手機尺寸完整執行既有 17 項相機／版面／參考照片／縮放測試，合共 21 次、0 失敗。記錄及截圖位於本機 `frontend/app/build/reports/system-permission-device/`。設定入口測試攔截並驗證指向本 App 的設定 Intent，再授予權限模擬返回；未操作各廠商的設定畫面。

固定控制排列版本（22f0e9d）曾在同一個 API 37（Android 17）模擬器切換為小手機、一般手機及平板尺寸：720×1280／320dpi、1080×2400／420dpi、1600×2560／320dpi。每種設定執行 17 項測試，共 51 次、0 失敗；已檢查各尺寸旋轉後的相機、刻度和參考縮圖截圖。該輪記錄位於本機 `frontend/app/build/reports/stable-controls-device/`，不提交編譯產物。

固定排列測試比較 0°／90°／180°／270° 的七個按鈕在裝置座標內的邊緣／中央距離，確認沒有換位；另檢查圖示、倍率按鈕及預覽的總旋轉角度。整合測試以實際螢幕點按操作橫向九宮格與快門，並在橫向拖動縮放；以感光元件到預覽的公開轉換矩陣驗證兩邊橫向之間的 180° 更新，並以 JPEG 像素尺寸及 EXIF 驗證橫直向保存方向。模擬器不能代替實際轉動手機的鏡頭／感測器驗證。

四項參考面板測試涵蓋入口、示範照片、選取後返回、關閉保留、清除、畫面重建、列表末端選取後重新開啟自動捲動、開啟時旋轉及返回關閉；另外驗證空列表、未知 ID 和無法解碼的圖片不會成為有效選擇。圖片載入與 Dialog 動畫完成後才擷取介面截圖。

刻度測試驗證中央指示固定、刻度移動及兩端淡出、按下不跳倍率、左右拖動方向、上下限與立即反向回應，以及鍵盤／無障礙調整；相機整合測試另確認拖動後鏡頭套用相同倍率。
按鈕切換測試另涵蓋鏡頭倍率範圍過濾、窄控制區四個按鈕不重疊、相機回饋不重複觸發請求、拖動後放手不誤點、取消／停用恢復按鈕，以及無障礙展開／收合。實際相機流程驗證拖動時預覽尺寸不變，快門與翻轉保持可見。

完整相機流程涵蓋預覽、切鏡後串流、雙指及刻度條縮放、倍率重設、閃光設定循環、九宮格、橫直旋轉與倍率恢復、背景返回、連按防重複、兩張 JPEG 的實際像素解碼及縮圖更新。已攔截並驗證點按縮圖發出的圖片開啟 Intent、保存 URI 及臨時讀取授權；未驗證各廠商圖片檢視器的畫面。虛擬鏡頭分別回報無閃光／固定倍率與有閃光／可變倍率，兩種控制能力都已驗證；這三種模擬尺寸不代表三部真機，實體鏡頭與閃光效果仍待真機測試。

Android 8／9 的儲存授權路徑尚未在裝置驗證。真機另檢查：

- 第一次開啟、允許／拒絕、重複拒絕後前往設定，以及從設定返回。
- 「僅限這次」失效後可重新請求；在設定撤銷權限後重開 App。
- 直向／橫向、切到背景／返回、鎖屏／解鎖後恢復預覽。
- 相機被其他 App 佔用、系統相機存取關閉及無鏡頭時有提示，可恢復或重試。
- 相簿可見、照片方向正確、儲存空間不足時可重試，沒有殘留未完成相片。

只有按快門才保存照片，影像不會上傳。

## 團隊協作

- 一個 repository 管理整個專案，一個工作項目一個分支，例如 `feat/camera-preview`。
- PR 說明變更、驗證方式與未完成部分，由另一位組員 review 後合併。
- main 保持可編譯、可啟動；提交前完成建置及 lint，畫面修改另在模擬器／真機檢查。
- 不提交個人設定、密鑰、模型權重、大量照片或研究參與者影像。
