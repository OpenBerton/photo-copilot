# NumPy 替換驗收記錄

驗證日期：2026-10-30。本次只替換儲存與搜尋，沿用 SigLIP 2、圖片處理、去重、拍法多樣性重排及 HTTP 格式。

## 索引與資料保留

- 現在使用 `config.toml` 的 `index_path = ".data/numpy-index"`；啟動時載入完整快照。
- 本機新索引包含 200 張照片、每張 768 維，向量與 JSON／manifest 合計 1,470,178 bytes。
- 為隔離儲存層差異，本次從舊索引的**副本**讀出既有向量、照片資料及模型簽章，寫入新目錄，沒有重新編碼這 200 張照片。新版執行時不包含這段一次性的轉換程式，也不需要 Qdrant。
- 另以真實 SigLIP 2 與六張照片執行新版離線建立流程，回報 `indexed: 6`、`dimension: 768`、`demo: false`，成功重開並核對路徑及簽章；亦實際執行離線索引 CLI，得到相同計數。這些驗證索引使用獨立暫存目錄。
- 遷移驗收時，324 個既有檔案／符號連結已核對 SHA256／連結目標，沒有變更。當時核對範圍包含原始照片、圖庫、署名、模型快取及舊 Qdrant 索引。
- 驗收後，使用者明確要求清理不再使用的 Qdrant 資料，已刪除舊索引與歷史備份。原始照片、圖庫、署名、模型快取及目前 NumPy 索引繼續使用；下方數據保留為遷移時的比較記錄。

新索引是按列對應的 float64 `.npy` 與 JSON，JSON 記錄 ID、路徑、標籤、來源、去重指紋、向量列雜湊及模型簽章。每代檔案寫入完成後，原子替換 `current.json`；載入時核對整檔雜湊、逐列雜湊、數量、維度、唯一 ID 和單位向量。已有 API 保留啟動快照，重建後需重啟才使用新版。之前的 NumPy 世代不自動刪除。

之後整批更新使用正常命令，從 catalog 重新編碼，無須舊 Qdrant：

```sh
uv run --project backend --locked --no-dev python -m photocopilot.index
```

後續團隊共用更新：指定模型權重改以 Git LFS 保存，200 張公開授權照片與目前 NumPy 世代一併版本管理。索引路徑改為相對路徑，讓 clone 到不同目錄仍可解析照片；資料修改後會重建對應雜湊，不跳過完整性校驗。啟動入口 `photocopilot.run` 使用隨附權重，若當前環境的模型／前處理簽章不同，先重新編碼隨附圖庫，再啟動。下列遷移結果是當時測量值，並非對所有組員電腦速度的保證；目前取得專案及試用步驟見 [README.md](README.md)。

## 搜尋結果比較

同一電腦、同一組既有向量、cosine 門檻 `0.65`、候選上限 `200`，比較舊本機 Qdrant 與 NumPy：

- 200 個庫內向量逐一作為查詢。
- 六張庫內照片重新經真實模型編碼，涵蓋食物、風景、人像各兩張。
- 五張未入這個圖庫的原示例照片重新編碼。

共 **211／211** 組的候選 ID、順序及最終至多六張推薦結果一致，候選數量介乎 1–57。最大 cosine 絕對差異為 **4.44 × 10⁻¹⁶**，屬浮點運算差異。新版本在同分時明確按 ID 排序；本批資料沒有造成順序差異的同分案例。這是替換一致性檢查，不是獨立的推薦品質評估。

## 耗時比較

Python 3.13.5、NumPy 2.5.4，CPU 推論。舊版 qdrant-client 1.20.0 使用本機持久化模式；比較時讀取舊索引副本。計時前暖機，交錯執行新舊呼叫，使用高精度時鐘。

| 範圍 | 舊 Qdrant 中位數／P95 | 新 NumPy 中位數／P95 |
| --- | --- | --- |
| 純搜尋：各 1,000 次，200 個向量 × 5 輪 | 1.435 / 2.115 ms | 0.210 / 0.473 ms |
| 完整推薦：各 40 次，8 張照片 × 5 輪 | 80.609 / 92.919 ms | 81.608 / 92.111 ms |

純搜尋包含正規化、相似度計算、門檻、排序及 Candidate／向量回傳，不含模型。NumPy 的搜尋中位數降低約 85%。完整推薦包含解碼、真實 CPU SigLIP 2、搜尋、去重與重排，不含 HTTP；40／40 次結果一致。完整流程中位數相差約 1 ms，模型及圖片處理仍佔主要耗時，本批結果不能證明整體推薦更快。數據僅適用本機 200 張圖庫，未驗證大型圖庫或併發負載。

## 實際驗收

- **38 個暫時自動測試全部通過**，0.171 秒。涵蓋索引重開、向量與資料對應、模型／前處理簽章、門檻等值、候選數量、同分、無效向量、資料破壞、首次及更新發布失敗重試、快照更新與實際 FastAPI ASGI 請求。首次發布失敗曾留下未發布檔案，已用失敗測試重現並修正；現在只清理該次嘗試建立的檔案。
- 另在正式依賴環境啟動新的 Uvicorn 程序，確認**沒有安裝 Qdrant、pytest 或 Ruff**。`/health` 回報 200 張、`demo: false`。
- 八次真實 HTTP 圖片上傳成功，涵蓋三類庫內照片及五張庫外示例；35 個回傳圖片網址全部可讀。驗證預設最多六張、分數門檻、回傳欄位及 `Cache-Control: no-store`。

- 按使用者要求，完成驗收後刪除本次暫時測試及比較程式，沒有將測試檔加入專案。保留本報告及忽略於 Git 的 `.data/numpy-migration-results.json` 實測數據。
